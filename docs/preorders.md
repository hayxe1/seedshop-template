# Заказы сверх остатка

Опубликованные товары можно заказать сверх остатка, включая нулевой остаток. Максимум — 99 упаковок одного товара или наборов одной позиции. Скрытые товары и наборы со скрытыми компонентами остаются недоступны.

В карточке товара кнопка «Под заказ» выбирает количество сверх наличия. Количество можно изменить самостоятельно. Корзина и оформление предупреждают о согласовании сроков. Для режима `PREORDER` согласование требуется при любом количестве; `UNLIMITED` не требует его.

Сервер заново проверяет наличие с учётом других активных резервов. Если товара не хватает, заказ сохраняется без создания платежа. В админке менеджер связывается с покупателем, вводит согласованный срок и нажимает «Срок согласован — разрешить оплату». Покупатель открывает сохранённую ссылку заказа, обновляет статус и оплачивает заказ. Срок виден покупателю и сохраняется в истории. Если перед созданием платежа нехватка увеличилась, потребуется новое согласование.

Для `TRACKED` резерв хранит два количества: `quantity` — доступные упаковки, `backorderQuantity` — недостающее количество. При успешной оплате списывается фактически выделенное количество, остаток не становится отрицательным. После поступления товара менеджер вносит новый остаток через существующую корректировку склада. Перевод оплаченного заказа в «Собран» списывает оставшиеся упаковки; при нехватке свободного остатка сборка отклоняется с объяснением. Для `PREORDER` и `UNLIMITED` складские движения не создаются.

Полный денежный возврат сохраняет прежнее правило автоматического восстановления склада: восстанавливается сумма фактических списаний за вычетом уже выполненных возвратных движений. Недостающее и ещё не поступившее количество не увеличивает склад. Повторные уведомления и позднее уведомление об оплате после возврата не списывают товар повторно и не отменяют статус возврата. Частичные возвраты требуют ручной проверки, как и прежде.

В этом самостоятельном шаблоне поля предзаказов уже входят в базовую миграцию `0001_template`. Для новой БД выполните штатный `prisma migrate deploy`, затем сгенерируйте Prisma Client. Не ищите две исторические миграции исходного магазина и не заменяйте миграцию на `db push`. Проверки выполняются только на отдельной базе с маркером `e2e` или `test`.

При поздней оплате после истечения резерва списывается только свободный остаток без количества, выделенного другим активным заказам. Недостача сохраняется как `backorderQuantity`, заказ отмечается для проверки склада менеджером. Задержанная отмена старой попытки оплаты не меняет новую попытку и её резерв. Это не ограничивает оформление заказа сверх остатка.
