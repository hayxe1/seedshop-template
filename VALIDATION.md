# Проверка извлечения — 16 октября 2026

Этот документ сохраняет результаты первоначального извлечения. Более поздние продуктовые изменения и новые проверки описаны в [docs/improvement-stage2.md](docs/improvement-stage2.md) и [результатах первого этапа](docs/improvement-results.md); сведения ниже о числе тестов и локальных процессах относятся к моменту извлечения.

Результат находится в отдельном проекте seedshop-template. Исходный b2bShop: 31eef68343a401bb8deb9bcb34a2c584b03a5c6c.

## Подтверждено

- Оригинал не изменён: Git чистый, SHA прежний, совпали SHA-256 всех 421 отслеживаемого файла. Исходные .env, данные, Git-история, товарные упаковки, seed и история миграций не копировались.
- Собственные зависимости установлены через npm ci в итоговой папке. Проверено независимое исполнение из неё. Интеграция с LeadForge не добавлялась.
- Prisma schema сохранена без изменений. Новая единственная миграция 0001_template применена к новым пустым demo и E2E БД. Добавлены требуемые checkout последовательность номеров и складские CHECK-ограничения. Prisma migrate diff не обнаружил расхождений schema и БД.
- Demo seed создал 6 товаров с условными ценами и собственными схематическими изображениями, один набор; заказов и покупателей при заполнении нет.
- Seed отказал без opt-in, на заполненной БД, с именем production-БД и с удалённым хостом. Содержимое всех таблиц до и после каждого отказа совпало по контрольной сумме.
- Отдельно проверены admin:create, хеширование пароля, вход и страницы /admin, /admin/catalog, /admin/orders на независимой demo-БД. Локальные данные входа хранятся только в игнорируемом .codex-tmp/local-admin.txt.
- Все 22 проверенных публичных маршрута и технических документа вернули HTTP 200; просмотрен полный HTML, включая метаданные и JSON-LD, manifest, robots и sitemap. Исходные контакты и реквизиты не найдены. Дополнительно проверены исходники уведомлений и платежное описание.
- Без ключей YooKassa настоящий POST /api/orders вернул 503 YOOKASSA_NOT_CONFIGURED с понятным сообщением и не создал заказ.
- Полный Chrome E2E: **77 passed, 3 skipped**. Пропущены только три теста аналитики, которые включаются отдельной переменной. Проверены каталог, поиск с кириллицей и словоформами, корзина, checkout, наборы, управление товарами и изображениями, склад, резервы, предзаказы, отмена и возврат через mock, защита приватных полей и доступа, подбор, календарь, ссылки, картинки и адаптивность 320–1440 px.
- npm run check прошёл: Prisma validate, TypeScript приложения и E2E, lint и production build. В lint остаётся одно исходное предупреждение next/no-location-assign-relative-destination в редакторе набора, ошибок нет.
- npm run smoke:standalone прошёл из итогового проекта: страницы, health, CSS, JS и изображения; Google Chrome без ошибок ресурсов.
- Шрифт Onest сохранён, перенесён в локальный файл с SIL OFL: сборка не зависит от доступности Google Fonts. Общие стили, компоненты, расположение элементов, анимации, логика склада и опта сохранены.

## Что исправлено в среде проверки

Первый тестовый кластер с locale C не выполнял регистронезависимое сравнение кириллицы. Для итоговых БД использована ICU ru-RU. Тесты адаптированы к отсутствию старого наполнения: сценарий смены статуса создаёт собственный изолированный заказ; проверки контактов ожидают нейтральные значения. Медиабиблиотека использует новые demo PNG.

Первый отдельный прогон аналитики исчерпал 20 соединений локального кластера при одновременных проверках. Лимит только этого изолированного PostgreSQL увеличен до 100; бизнес-код не менялся. Дополнительно сработал накопленный лимит входов предыдущих прогонов; защита магазина не менялась. На ещё одной новой ICU E2E-БД все 3 теста аналитики прошли.

## Внешние границы

- Настоящие платежи, внешние тестовые реквизиты YooKassa, реальные webhook из сети и фискализация не проверялись. Локальные тесты использовали существующий mock; в production он заблокирован.
- Реальная доставка email/Telegram не проверена, ключи и получатели не настроены. Во время E2E внешние уведомления принудительно отключены.
- Docker daemon в этой среде не запущен: сборка Docker-образа и развёртывание на VPS, HTTPS/DNS, production cron, backup/restore и мониторинг не проверены. Их исходные механизмы сохранены с нейтральными путями; автоматическая публикация и production workflow требуют настройки клиента.
- Юридические страницы — явно незаполненная структура. Доставка по Воронежу, существующие оптовые правила и подарочная упаковка 50 ₽ требуют согласования с клиентом перед продажами.
- Это проверенное локальное извлечение полноценного магазина; готовность конкретного клиентского production подтверждается только после его настроек и staging-проверки по README.
