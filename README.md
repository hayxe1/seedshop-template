# seedshop-template

Независимый интернет-магазин семян и садовых товаров на Next.js 16, React 19, TypeScript, Prisma 7 и PostgreSQL. Извлечён из b2bShop версии `31eef68343a401bb8deb9bcb34a2c584b03a5c6c`. Исходная архитектура, стили, адаптивность и коммерческая логика сохранены. Перед реальными продажами требуется адаптация данных и инфраструктуры продавца.

Сохранены каталог, категории, поиск, фильтры, галереи, корзина, оформление заказа, YooKassa, управление заказами и товарами, складские движения, резервы, предзаказы, существующее оптовое поведение, наборы с черновиком и публикацией, подбор семян, календарь, уведомления, аналитика с согласием и SEO.

## Локальный запуск

Нужны Node.js 22+, npm и PostgreSQL 17+; Google Chrome нужен для E2E. Создайте **новую** БД и отдельного пользователя. Код не требует доступа к исходному магазину.

Для русского поиска БД должна поддерживать регистронезависимое сравнение кириллицы. Рекомендуется UTF-8 и ICU `ru-RU`; libc locale `C` не подходит. Пример создания демонстрационной БД (параметры подключения PostgreSQL задайте для своей установки):

```powershell
createdb --template=template0 --encoding=UTF8 --locale-provider=icu --icu-locale=ru-RU seedshop_template_demo
Copy-Item .env.example .env
```

В `.env` заполните `DATABASE_URL` **только новой БД**, `SITE_URL`/`NEXT_PUBLIC_SITE_URL` и уникальные случайные `ADMIN_AUTH_SECRET`, `ORDER_ACCESS_SECRET`, `CRON_SECRET`. Настоящие платёжные ключи для локальной презентации не нужны. Затем:

```powershell
npm ci
npm run prisma:generate
npm run prisma:deploy
# Необязательно: только для пустой локальной БД с отдельным словом demo в имени.
$env:TEMPLATE_DEMO_DATABASE = 'seedshop-template-demo'
npm run demo:seed
Remove-Item Env:TEMPLATE_DEMO_DATABASE
npm run dev -- --hostname 127.0.0.1
```

Откройте `http://127.0.0.1:3000`. `predev` применяет миграции и генерирует Prisma Client, но не запускает seed. Если выбрали другой порт, укажите его и в URL окружения.

`prisma/migrations/0001_template` — новая единственная базовая миграция из актуальной schema, дополненная SQL-последовательностью номеров заказов и складскими CHECK-ограничениями. Истории прежних миграций и исходного `prisma/seed.mjs` здесь нет. Используйте `migrate deploy`, а не `db push`, иначе служебные SQL-объекты не появятся.

`demo:seed` создаёт 7 явно помеченных товаров с условными ценами и авторскими схематическими изображениями, а также один набор. Есть разные фасовки и пропорции медиа, товар без фото, остаток 2, нулевой остаток, предзаказ и товар без ограничения склада. Все свойства демонстрационные. Он требует явного opt-in, loopback-хост и demo-маркер в имени БД, проверяет пустоту всех прикладных таблиц в транзакции, не удаляет и не перезаписывает данные. Повторный запуск на заполненной demo-БД завершится отказом. Администратора, заказов и покупателей он не создаёт.

## Администратор

Задайте `TEMPLATE_ADMIN_EMAIL` и уникальный `TEMPLATE_ADMIN_PASSWORD` длиной от 16 символов в локальном окружении, выполните `npm run admin:create`, затем удалите эти переменные. Пароль не выводится; существующая учётная запись не перезаписывается. Вход: `/admin/login`. Общего пароля по умолчанию в демонстрационной или клиентской БД нет.

## Проверки

```powershell
npm run prisma:validate
npm run typecheck
npm run typecheck:e2e
npm run lint
npm run build
npm run smoke:standalone
```

Для каждого полного прогона рекомендуется новая пустая тестовая БД: повторные прогоны на одной БД сохраняют тестовые данные и могут упереться в штатные лимиты входа/заказов. Для E2E создайте **другую** локальную БД с маркером `e2e` или `test`, той же корректной сортировкой кириллицы, и задайте `E2E_DATABASE_URL`:

```powershell
npm run test:e2e
$env:E2E_ENABLE_ANALYTICS = '1'
npm run test:e2e -- tests/e2e/analytics.spec.ts
Remove-Item Env:E2E_ENABLE_ANALYTICS
```

Runner применяет миграцию, добавляет отдельные тестовые фикстуры без удаления прежних данных, использует Chrome и порт 3100. Только в этой явно изолированной БД создаётся известная тестовая учётная запись. Runner отключает email/Telegram и подставляет фиктивные платёжные реквизиты с `YOOKASSA_E2E_MOCK=1`; обращения к настоящей YooKassa не нужны. В production этот mock заблокирован. Удаляющие тестовые helpers ограничены маркированной БД — никогда не направляйте их на БД клиента.

Без `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` сервер безопасно сообщает о недоступности онлайн-оплаты. Кнопка checkout и обработка заказов остаются настоящими; оплачиваемый заказ требует настроенной YooKassa либо изолированного E2E mock.

## Где адаптировать под клиента

| Что | Файлы |
| --- | --- |
| Имя и логотип словами | `src/shared/config/store.ts` — общая витрина, админка, manifest, SEO и уведомления; редакционные тексты страниц проверяются отдельно |
| SEO, социальная картинка | `src/lib/seo.ts`, `src/app/layout.tsx`, `src/app/(storefront)/page.tsx` |
| Логотип, подписи, иконка | `src/shared/ui/storefront-header.tsx`, `storefront-footer.tsx`, `src/app/admin/admin-shell.tsx`, `src/app/icon.svg`, `src/app/manifest.ts` |
| Контакты и реквизиты | `src/app/(storefront)/contacts/page.tsx`, `requisites/page.tsx` |
| Документы и версия согласия | `src/app/(storefront)/offer/page.tsx`, `privacy/page.tsx`, `src/shared/legal/version.ts` |
| Тексты и изображения | `src/features/home/`, `public/home/`, `public/category-icons/`, `public/sets/` |
| Уведомления и назначение платежа | `src/server/commerce/notification-worker.ts`, `src/lib/yookassa.ts`, `EMAIL_FROM` |
| Каталог и остатки | Существующая админка `/admin/catalog`; реальные данные загружаются отдельно |
| Инфраструктура | `.env.example`, `docker.env.example`, `Dockerfile`, `docker-compose.yml`, `deploy/` |

Шрифтовой файл Onest включён локально с лицензией SIL OFL в `src/app/fonts/OFL.txt`, поэтому сборка не скачивает шрифт. Общие изображения сада и овощей сохранены для прежнего оформления; товарные упаковки и каталог исходного продавца исключены. Демонстрационные схемы лежат в `public/demo/` и `public/product-images/demo/`.

## Обязательные настройки до production

- Заполнить название, контакты, адрес, реквизиты и собственные тексты продавца; заменить демонстрационный ассортимент, цены, остатки и изображения.
- Подготовить и согласовать оферту/политику, установить принятую версию согласия. Сейчас это явно обозначенная структура для заполнения, а не действующие документы клиента.
- **Доставка пока ограничена Воронежем**: бесплатный самовывоз и отдельно согласуемый местный курьер. Это сохранённое правило. Проверить `src/app/api/orders/route.ts` (`isVoronezhAddress`), `src/app/(storefront)/checkout/page.tsx`, страницы delivery/about/faq, `src/features/home/content.ts`, подписи в админке и SEO. Изменение региона — обязательная клиентская адаптация.
- Согласовать текущие складские, оптовые и предзаказные правила с клиентом. Заказ сверх остатка сохранён для оптовых покупок и согласуется менеджером. Цена подарочной упаковки 50 ₽ имеет общий источник для сервера и витрины: `src/shared/config/commerce.ts`.
- Создать отдельные production БД и администратора, установить уникальные секреты, домен, HTTPS, `SITE_URL` и `NEXT_PUBLIC_SITE_URL` на этапе сборки и запуска; удалить demo/E2E-переменные.
- Настроить действующие реквизиты YooKassa, чек/налоговые параметры и webhook `/api/yookassa/webhook`; проверить тестовый магазин провайдера перед приёмом настоящих платежей. Локальная платёжная имитация не подтверждает работу внешнего провайдера.
- При необходимости настроить email/Telegram, домен отправителя и получателей; проверить доставку. Без этих настроек продавец работает через админку.
- Настроить commerce cron, резервные копии, восстановление и мониторинг. Проверить доставку заказа, оплату, отмену/возврат и склад на клиентском staging.
- Настроить реестр контейнеров и `REMOTE_IMAGE`. Привязок к прежнему домену, серверу и реестру нет. Публикация образа в CI выключена до `ENABLE_IMAGE_PUBLISH=1`; production-workflow сохранён как `deploy/production-workflow.yml.example` и требует осознанной установки и настроек клиента. Скрипты деплоя, backup/restore и systemd сохранены.
- Проверить canonical, sitemap, robots, JSON-LD и публичные документы на финальном домене, заполнить собственные идентификаторы аналитики и верификации.
