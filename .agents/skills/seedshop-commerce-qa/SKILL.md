# Проверка коммерческого пути Seedshop

Работай из корня seedshop-template. Прочитай README.md, package.json и относящийся к изменению раздел docs/commerce-operations.md или docs/preorders.md. Сведения ниже — карта существующих путей; перед выполнением сверяй актуальные команды.

## Подготовка без записи

Запусти `node .agents/skills/seedshop-commerce-qa/scripts/preflight.mjs`. Он проверяет файлы, Chrome и безопасные признаки конфигурации; не открывает соединение, не выводит URL/секреты и не подтверждает доступность БД. Код 2 означает, что автоматический E2E пока не готов; независимые статические проверки доступны.

Для перечня тестов используй `node node_modules/@playwright/test/cli.js test --list`. Wrapper `npm.cmd run test:e2e` выполняет миграции и seed даже с аргументом --list.

## Среда E2E

E2E_DATABASE_URL задаётся в локальном окружении либо .env и указывает на отдельную одноразовую PostgreSQL БД. Не печатай значение. Требования текущего prisma/demo-seed.mjs строже проверки runner: loopback-хост, отдельный маркер test/e2e в имени, отделённый подчёркиваниями, и DATABASE_URL=E2E_DATABASE_URL внутри дочерней среды. Используй имя вроде seedshop_template_e2e. Для русского поиска нужна корректная кириллическая сортировка; README рекомендует ICU ru-RU.

Не направляй тесты в демонстрационную, клиентскую или исходную БД. Одного маркера в имени недостаточно: установи назначение базы. Перед полным прогоном предпочитай новую пустую тестовую БД — фикстуры и лимиты сохраняются между запусками. Не удаляй существующую БД для очистки без поручения.

Runner scripts/run-e2e-suite.mjs применяет миграции и seed, подменяет оплату на YOOKASSA_E2E_MOCK и очищает реквизиты email/Telegram в дочернем окружении. Playwright запускает собственный сервер на 3100 (или E2E_PORT), один worker, Chrome, без reuseExistingServer. Не запускай несколько suite на одной БД/порту. Подмена сайта и фикстур не подтверждает работу провайдера.

## Выбор проверок

| Изменение | Существующие spec в tests/e2e/ |
| --- | --- |
| Поиск и каталог | global-search, catalog-search-helper, catalog-categories, catalog-pagination, product-page-navigation |
| Карточка, корзина и checkout | cart, checkout-product, product-page-navigation |
| Наборы и публикация | checkout-seed-set, seed-set-publication, sets-catalog-cta |
| Предзаказ, оплата, обработка | preorder, checkout-product, admin-orders; прочитай реальные assertions перед выводами |
| Админка и товары | admin-catalog, admin-products, admin-orders |
| UI, адаптивность и доступность | storefront-qa, home-redesign плюс проверка изменённых страниц в браузере |
| Доступ и безопасность | security-hardening плюс подходящий security review по объёму задачи |
| Аналитика | analytics с E2E_ENABLE_ANALYTICS=1 в отдельном процессе/прогоне |

К каждому имени добавляется .spec.ts. Например: `npm.cmd run test:e2e -- tests/e2e/checkout-product.spec.ts tests/e2e/admin-orders.spec.ts`.

Проверяй действительные переходы заказа, PaymentAttempt, резерва и склада в актуальных моделях и assertions. Не считай storefront-yookassa.spec.ts полной проверкой платёжного протокола: он проверяет публичные страницы и видимость товаров. Для изменённого критического перехода, не покрытого существующими тестами, добавь адресный сценарий.

Статические команды: prisma:validate, typecheck, typecheck:e2e, lint, build через npm.cmd run. Финальная продуктовая цель требует полного применимого набора и E2E; для узкого изменения сначала выполняй соответствующую проверку. У smoke:standalone предварительно изучи действующий скрипт и условия запуска.

## Свидетельства результата

Сохраняй команды, результаты и список реально проверенных переходов; артефакты — в .codex-tmp/ или штатных игнорируемых отчётах. Для UI проверяй desktop/mobile, ошибки и длинный контент. Не меняй реальные товары ради скриншота.

Разделяй: статическую проверку, браузерный сценарий с mock, тест внешнего провайдера и production. При недоступности внешнего сервиса фиксируй точную границу и продолжай независимую работу. Устанавливай причину зависания и владельца процесса перед остановкой; не завершай все node/Chrome/Postgres процессы системы.
